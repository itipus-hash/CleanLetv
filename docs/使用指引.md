# 使用指引：乐视电视装桌面

> 本项目：**CleanLetv**，基于 [CleanYourTV](https://github.com/Gathin23/cleanyourtv) 的乐视适配版
> 上游源码：MIT 协议，基于 commit `0ed6c5b` 修改
> 实测机型：乐视 X4-65S（Android 6.0 / SDK 23，MStar 芯片）

---

## 一、这个项目是什么

在乐视电视上装一个极简 Apple TV 风格的桌面，并把被固件劫持的遥控器按键夺回来：

1. **换桌面** — 编译安装原生 Android TV 桌面（纯黑背景、底部程序坞、玻璃高光跟随）
2. **按键重映射** — 乐视固件在框架层吃掉 Le 键、语音键，改写系统 keylayout 绕过去
3. **Le 键全局应用库** — 在任何 App 里按 Le 键浮出应用库/每日一言，不跳回桌面
4. **每日一言** — 9896 条本地语句库，离线可用

**与通用版 CleanYourTV 的区别**：通用版在乐视上装完只有一半能用——设置键会被乐视的常驻系统窗口盖住、Le 键弹的是乐视自己的视频、返回键落回原厂桌面、输入源键没反应。本仓库把这些一并解决。

### 需要什么

| 项 | 要求 |
|---|---|
| 电视 | 乐视 X4-65S（其它型号未验证，原理可参考 `开发文档.md`） |
| root | **必须**（要改 `/system` 的 keylayout 并装守护进程） |
| ADB | 开启并授权（网络 ADB 5555 或 USB） |
| 本机 | Android SDK + JDK 17+ |

## 二、准备

### 电视端开调试

`设置` → 关于本机 → 连点版本号 7 次进开发者选项 → 打开「USB 调试」（网络 ADB 再开「ADB 调试」）。
本机已 root，装好 SuperSU 后**在 SuperSU 里给「Shell」和「ADB」授永久权限**——后面所有 `su` 命令都会用到。

### 确认电视 IP

```bash
adb connect 192.168.199.126:5555
adb shell getprop ro.product.model
```

### 连通性自检

```bash
python tools/tv.py --probe
```

## 三、编译与安装

### 1. 编译

```bash
cd launcher
export ANDROID_HOME=<你的 Android SDK 路径>
./gradlew assembleDebug
```

### 2. 推送安装

```bash
# 这台固件的 adbd SYNC 协议会挂死，adb push 传不动，必须用 b64push
python tools/b64push.py launcher/app/build/outputs/apk/debug/app-debug.apk /data/local/tmp/tvhome.apk
adb shell "pm install -r -d /data/local/tmp/tvhome.apk"
```

### 3. 装机收尾（**不能省**）

```bash
adb shell "am force-stop com.gathin.tvhome"
adb shell "settings put secure enabled_accessibility_services com.gathin.tvhome/.HomeKeyService"
adb shell "settings put secure accessibility_enabled 1"
adb shell "input keyevent 3"    # HOME，把被屏保抢走的焦点唤回桌面
```

> ⚠️ `pm install -r` 会清空无障碍设置，`am force-stop` 会连带关掉同进程的无障碍服务。
> 上面三行少一行，**设置键就会莫名其妙失灵**。

验证：

```bash
adb shell "dumpsys accessibility"    # 应看到 Service[label=主页键, ... capabilities=8]
adb shell "dumpsys window windows" | grep mCurrentFocus   # 应是 com.gathin.tvhome/.MainActivity
```

## 四、部署按键重映射（需要 root）

### 为什么必须改系统文件

乐视固件的 `PhoneWindowManager` 在框架层按 keycode 拦截 Le 键、语音键、设置键，事件**根本到不了应用层**。改写 keylayout 文件把 keycode 换掉，固件那段匹配就不命中了。

```bash
adb push scripts/fixkl.sh /data/local/tmp/
adb shell "su -c 'mount -o rw,remount /system'"
adb shell "su -c 'sh /data/local/tmp/fixkl.sh'"
adb reboot      # .kl 开机只读一次，必须重启生效
```

> ⚠️ **SuperSU 的挂载命名空间隔离**：普通 `su -c` 里的 remount 只作用于该会话的私有命名空间，**返回成功但全局仍是 ro**。必须用 `su --mount-master -c "mount -o remount,rw /system; ..."`，且 cp/chmod 写在同一个会话里。写入前先 `grep ' /system ' /proc/mounts` 确认是 `rw`，别信返回码。

`fixkl.sh` 是幂等的，重刷固件后重跑一次即可恢复。

## 五、部署 Le 键守护进程（需要 root）

固件会在别的 App 到前台约 0.5 秒后 force-stop 所有持有无障碍服务的包，所以 App 级的全局按键监听做不到。用一个 root 守护进程直接读 `/dev/input`。

```bash
adb push dbg/lekeyd/lekeyd dbg/lekeyd/lekeyd.sh dbg/lekeyd/leplay.sh dbg/lekeyd/install-recovery-2.sh /data/local/tmp/
adb shell "su -c 'cp /data/local/tmp/lekeyd /system/bin/ && chmod 755 /system/bin/lekeyd'"
adb shell "su -c 'cp /data/local/tmp/lekeyd.sh /system/bin/ && cp /data/local/tmp/leplay.sh /system/bin/ && chmod 755 /system/bin/lekeyd.sh /system/bin/leplay.sh'"
adb shell "su -c 'cp /data/local/tmp/install-recovery-2.sh /system/etc/ && chmod 755 /system/etc/install-recovery-2.sh'"
adb reboot
```

验证（按一次 Le 键）：

```bash
adb shell "su -c 'tail -3 /data/local/tmp/lekeyd.log'"
# 期望：scancode 189 on /dev/input/event2 -> toggle
```

> 改完 lekeyd 二进制要 `kill -9 <pid>` 让看护脚本重启它。**别用 `pidof`**——这台机器上它会展开成整张进程表，杀掉一大片进程导致软重启。用 `ps | grep lekeyd`。

## 六、修复设置键

乐视的 `com.stv.globalsetting` 服务常驻一个 `TYPE_PHONE` 窗口（`ty=2008`），永远压在桌面面板之上——面板确实启动了、焦点也是我们的，但被整层盖住。代码层面无解，只能让那扇窗消失：

```bash
TV_HOST=192.168.199.126 bash tools/letv-buttons.sh
```

Windows：

```powershell
$env:TV_HOST='192.168.199.126'; powershell -ExecutionPolicy Bypass -File .\tools\letv-buttons.ps1
```

脚本幂等，会自己按设置键验证焦点落在哪。

## 七、推主题（可选）

主题 JSON 控制列数、程序坞行数、每日一言开关与分类、按键映射等，**改主题不用重编译**。

```bash
python tools/b64push.py themes/letv-x4/config.json /sdcard/Android/data/com.gathin.tvhome/files/config.json
adb shell "su -c 'cp -f /sdcard/Android/data/com.gathin.tvhome/files/config.json /data/data/com.gathin.tvhome/files/config.json'"
adb shell "am force-stop com.gathin.tvhome"
adb shell "settings put secure enabled_accessibility_services com.gathin.tvhome/.HomeKeyService"
adb shell "settings put secure accessibility_enabled 1"
adb shell "am start -n com.gathin.tvhome/.MainActivity"
```

完整键表见 `../themes/README.md`。

## 八、去广告

与桌面无关的通用去广告（停用厂商遥测、广告服务、推荐位）用上游自带的清单：

```bash
TV_HOST=192.168.199.126 bash tools/disable.sh examples/<你的机型>/debloat.txt
```

**停用不是卸载，随时可恢复**（`tools/restore.sh`）。

## 九、收尾（重要）

电视上手动关闭调试：

1. 关闭「USB 调试」和「网络 ADB」
2. 在「已授权的设备」里撤销本机
3. 重启电视

> ⚠️ 本项目的守护进程以 root 身份常驻，直接读 `/dev/input`。调试开着等于把电视的输入设备暴露在局域网上。

验证：

```bash
python tools/adb-closed.py 192.168.199.126
```

## 十、遇到问题

| 现象 | 多半是 |
|---|---|
| 设置键没反应 / 弹乐视自己的抽屉 | `GlobalSettingService` 没禁用 → 跑第六步 |
| 设置键时灵时不灵 | 无障碍服务被关掉了 → 跑第三步的收尾命令 |
| Le 键没反应 | 守护进程没起来 → 看 `/data/local/tmp/lekeyd.log` |
| Le 键在别的 App 里没反应 | 电视端改过系统文件 → 重跑第四步 |
| 桌面在后台时按键全无反应 | 固件把无障碍宿主一起杀了 → 这就是 lekeyd 存在的理由 |
| 桌面黑屏，焦点在 RecyclerView | 手机遥控 App 进了 touch mode → 重启桌面 |

更细的排查步骤见 `开发文档.md` 的「调试与验证方法」和「坑与禁忌」。
