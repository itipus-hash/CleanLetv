# 迁移文档：把桌面装到另一台同型号乐视 TV

> 场景：`app-debug.apk`（CleanYourTV 桌面，`com.gathin.tvhome`）安装到**另一台同型号乐视电视**后，还需要做哪些操作才能达到当前这台（实测基准机）的效果。
> 只装 APK 的话：桌面能跑，但设置键会被乐视抽屉盖住、Le 键弹乐视视频、返回键落回乐视原生桌面、输入源键没反应。
> 配套阅读：定制原理看 `开发文档.md`，上手步骤看 `使用指引.md`。
> 最后更新：2026-10-23

---

## 0. 适用范围与前置条件

| 项 | 要求 |
|---|---|
| 电视型号 | 乐视 X4-65S（DemeterUHD）或**同固件**机型（Android 6.0 / MStar / 同 keylayout 文件） |
| 调试 | 已开网络 ADB（5555），电脑能 `adb connect` |
| **root** | **完整迁移流程需要**。步骤 3/4/5/7 都要 `su`（这台有 SuperSU，`su -c` 无确认框）。只做步骤 1/2 的话——也就是换桌面 + 每日一言 + 应用库面板——**不需要 root** |
| root 来源 | 实测这台机器是「刷乐视底包 → 刷精简包 → 拿到 root」。**刷机步骤不在本仓库范围内**，本清单只覆盖 root 之后的增量改造 |
| 文件 | APK：`launcher/app/build/outputs/apk/debug/app-debug.apk`；脚本：`dbg/fixkl.sh`；守护进程：`dbg/lekeyd/{lekeyd,lekeyd.sh,leplay.sh,install-recovery-2.sh}`；主题：`themes/letv-x4/config.json` |

> 不是同固件的机器：.kl 文件名和 scancode 可能不同，先按 `开发文档.md` §7.2 取证再决定，不要照抄。

## 1. 快速清单（TL;DR）

| # | 操作 | 需要 root | 重启后保持 | 难度 |
|---|---|---|---|---|
| 1 | 安装 APK | 否 | 是（重装才丢） | 易 |
| 2 | 装机收尾：恢复无障碍服务 + 回桌面 | 否 | 是（仅 force-stop/重装丢） | 易 |
| 3 | 停用原厂桌面 `com.stv.launcher` | **是** | 是 | 易 |
| 4 | 停用乐视抽屉服务 `com.stv.globalsetting` | **是** | 是 | 易 |
| 5 | 按键重映射：remount + `fixkl.sh` + 部署 `lekeyd` 守护进程 + 重启 | **是** | **是（重刷固件丢）** | 中 |
| 6 | 推送乐视主题 | 部分（cp 那步） | 是 | 易 |
| 7 | （可选）删除开机视频 | **是** | 是（重刷固件丢） | 中 |
| 8 | 验证清单（见 §2 步骤 8） | 否 | — | — |

全程约 15-20 分钟，其中只有一次重启（步骤 5 后）。

## 2. 详细步骤

以下命令在 **Git Bash** 执行，`TV` 换成新电视的 IP：

```bash
export MSYS_NO_PATHCONV=1
TV=192.168.199.XXX
adb connect $TV:5555
```

### 步骤 0：确认机器

```bash
adb -s $TV:5555 shell "getprop ro.product.model; getprop ro.build.version.release; getprop ro.serialno"
adb -s $TV:5555 shell "su -c id"        # 期望 uid=0(root)，不是就先去开 root
adb -s $TV:5555 shell "ls /system/usr/keylayout/ | grep -E '3697_0001|4c65_3d4c'"
```

最后一条应看到两个文件（红外 + 蓝牙遥控的 keylayout）。**看不到就先别做步骤 5**，按 `开发文档.md` §7.2 取证实际文件名。

### 步骤 1：安装 APK（必须走 b64push）

这台固件的 adb SYNC 协议挂死，`adb push`/`adb install`（走本地文件参数时）不可靠，标准动作是先传后装：

```bash
cd .
./tools/venv/Scripts/python.exe -I tools/b64push.py launcher/app/build/outputs/apk/debug/app-debug.apk /data/local/tmp/tvhome.apk
adb -s $TV:5555 shell "pm install -r -d /data/local/tmp/tvhome.apk"
```

期望 `Success`。装完**先不启动**，继续步骤 2。

### 步骤 2：装机收尾（每次 force-stop/重装后都要做）

`am force-stop` 会连带关掉和桌面同进程的无障碍服务 `HomeKeyService`，导致设置键失灵：

```bash
adb -s $TV:5555 shell "am force-stop com.gathin.tvhome; settings put secure enabled_accessibility_services com.gathin.tvhome/.HomeKeyService; settings put secure accessibility_enabled 1; sleep 2; input keyevent 3"
```

验证：

```bash
adb -s $TV:5555 shell "settings get secure enabled_accessibility_services; settings get secure accessibility_enabled; dumpsys window | grep -m1 mCurrentFocus"
# 期望：com.gathin.tvhome/.HomeKeyService / 1 / Window{... com.gathin.tvhome/com.gathin.tvhome.MainActivity}
```

> `input keyevent 3`（HOME）是把桌面唤到前台——force-stop 后焦点常被乐视屏保 `com.stv.screenflyter` 抢走。这条设置了之后**重启电视不会丢**（存在 Settings.Secure 里开机自恢复），只有 force-stop / 重装 APK 会丢。

### 步骤 3：停用原厂桌面（否则"返回"落回乐视原生界面）

乐视原厂桌面 `com.stv.launcher`（T2Launcher）是 PERSISTENT、uid 1000 常驻，`am force-stop` 杀不掉。它开着的话，任何 App 返回时 HOME 都解析到它——用户看到的就是"返回是乐视原生界面"。

```bash
adb -s $TV:5555 shell "su -c 'pm disable-user --user 0 com.stv.launcher'"
```

- 重启后保持（disable-user 状态持久化），**但重刷固件会恢复**。
- 验证：`adb -s $TV:5555 shell "su -c 'cmd package list packages -e 2>/dev/null | grep stv.launcher'"` 或直接按 HOME 看落到哪。注意 `pm list packages -d` 在 Android 6.0 无输出，别用它判断。
- 恢复：`su -c 'pm enable com.stv.launcher'`。

### 步骤 4：停用乐视抽屉服务（否则设置键面板被盖住）

乐视 `com.stv.globalsetting/.service.GlobalSettingService` 常驻一个 TYPE_PHONE 全屏窗口，永远压在我们的面板之上——面板确实启动了但看不见（`dumpsys window` 里 `mFocusedApp` 是我们的、`mCurrentFocus` 是乐视的）。

```bash
adb -s $TV:5555 shell "su -c 'pm disable com.stv.globalsetting/.service.GlobalSettingService'"
```

- 禁的是**服务**不是 Activity，乐视自己的「系统设置」App 照常可用。
- shell（uid 2000）执行会 SecurityException，必须 `su -c`。
- 恢复：`su -c 'pm enable com.stv.globalsetting/.service.GlobalSettingService'`。
- 或者直接用仓库封装好的一键脚本（幂等，自带自检）：`TV_HOST=$TV bash tools/letv-buttons.sh`。

### 步骤 5：按键重映射 + 全局 Le 键守护进程（核心步骤）

背景：固件在 `PhoneWindowManager.interceptKeyBeforeQueueing` 按 keycode 吃掉两颗键（scancode 377→keycode 4415 LETV→**截图**；scancode 189→keycode 4431 LE→乐视视频），应用层永远收不到。解法是**只把 189 改成 F5** 绕过拦截；应用侧和守护进程都只认 scancode，所以映射成什么不影响功能。

**377 必须保持 LETV**：那颗键就是遥控器上设置键下面的**分享/截图键**，固件的 `takeScreenshot` 正是要保留的功能（截图存 `/sdcard/Pictures/Screenshots/*.jpg`，并弹"截图成功"提示）。早期把两颗键一起改成 F5，结果截图键变成了应用库——`fixkl.sh` 现在会把 377 一律写回 `LETV`，所以跑一遍即可修复。

**第三颗键：语音键（scancode 167）→ F6**。它在分享键下面，固件会为它去起 `com.stv.voice/.WindowService`（本机没这个包），所以只响两声"滴嘟"、什么都不做。改成 F6 后由桌面接管：**一键打开用户在电视上指定的 App**，没指定过就弹选 App 列表（只列自己装的 App）。两声"滴嘟"保留，是这颗键唯一的反馈。详见 `开发文档.md` §4.6b。

**为什么是 F5 而不是 MENU**：MENU 会让焦点所在的 App 弹出它自己的选项菜单——在别的 App 里按 Le 就变成"弹出那个 App 的菜单"（这正是要修的毛病）。F5 框架不特殊处理、几乎没有电视 App 绑定。

**为什么还要守护进程**：固件在别的 App 到前台后约 0.5s 会 force-stop 所有持有无障碍服务的包（连专门的小包也杀），所以 App 层做不了全局监听。`lekeyd` 是 root 进程，直接读 `/dev/input`，不受影响。原理详见 `开发文档.md` §4.7。

```bash
# 5.1 /system 可写（ext4 无 dm-verity；重启自动回 ro 但文件改动持久）
# 注意必须用 su --mount-master：SuperSU 默认开启挂载命名空间隔离，普通 su -c 里的
# remount 只影响该会话，会"返回成功但仍是 ro"（2026-10-23 踩到两次）。
adb -s $TV:5555 shell "su --mount-master -c 'mount -o remount,rw /system; grep \" /system \" /proc/mounts'"
# 期望看到 rw

# 5.2 推送并执行 .kl 修复脚本（幂等：189 一律改 F5，167 一律改 F6，377 一律写回 LETV，已备份过不重复备份）
cd .
./tools/venv/Scripts/python.exe -I tools/b64push.py dbg/fixkl.sh /data/local/tmp/fixkl.sh
adb -s $TV:5555 shell "su --mount-master -c 'sh /data/local/tmp/fixkl.sh'"
# 期望输出：两个文件里 key 377 是 LETV、key 189 是 F5、key 167 是 F6，权限 644 root:root
#          备份在设备 /data/local/tmp/kl-backup/

# 5.3 部署 lekeyd（4 个文件都进 /system，755 root:root）
./tools/venv/Scripts/python.exe -I tools/b64push.py dbg/lekeyd/lekeyd            /data/local/tmp/lekeyd
./tools/venv/Scripts/python.exe -I tools/b64push.py dbg/lekeyd/lekeyd.sh         /data/local/tmp/lekeyd.sh
./tools/venv/Scripts/python.exe -I tools/b64push.py dbg/lekeyd/leplay.sh         /data/local/tmp/leplay.sh
./tools/venv/Scripts/python.exe -I tools/b64push.py dbg/lekeyd/install-recovery-2.sh /data/local/tmp/install-recovery-2.sh
adb -s $TV:5555 shell "su --mount-master -c 'cp /data/local/tmp/lekeyd /system/bin/lekeyd; cp /data/local/tmp/lekeyd.sh /system/bin/lekeyd.sh; cp /data/local/tmp/leplay.sh /system/bin/leplay.sh; cp /data/local/tmp/install-recovery-2.sh /system/etc/install-recovery-2.sh; chown root:root /system/bin/lekeyd /system/bin/lekeyd.sh /system/bin/leplay.sh /system/etc/install-recovery-2.sh; chmod 755 /system/bin/lekeyd /system/bin/lekeyd.sh /system/bin/leplay.sh /system/etc/install-recovery-2.sh'"

# 5.4 重启（.kl 开机时读取，不重启不生效；lekeyd 也由开机脚本拉起）
adb -s $TV:5555 shell reboot
```

重启后桌面会自动起来（HOME 候选只剩我们）。**重刷固件后必须重跑 5.1-5.4**（.kl 和 /system 下的四个文件都会恢复原样）。

如果步骤 0 发现 .kl 文件名不同，照 `fixkl.sh` 的模式手改：`key 377 LETV` 保持不动，`key 189 LE` sed 成 `key 189 F5`，`key 167 DVR`（或 `RECORD`）sed 成 `key 167 F6`，并确认设备 `dumpsys input` 里遥控器实际绑的是哪个 .kl。

**部署后自检**：

```bash
adb -s $TV:5555 shell "su -c 'ps | grep lekeyd'"                     # 期望恰好 1 个（别用 pidof，见开发文档 §9）
adb -s $TV:5555 shell "su -c 'cat /data/local/tmp/lekeyd.log'"       # 期望有 lekeyd started + watching /dev/input/eventN
```

若守护进程没起来：看 `/system/etc/install-recovery-2.sh` 是否存在且 755；手动跑 `su -c 'sh /system/bin/lekeyd.sh'` 看报错（最常见的两个坑：`DF_1_PIE` 未清导致 `unsupported flags DT_FLAGS_1`、`ANDROID_ROOT` 未 export 导致 `am` 起不来）。

### 步骤 6：推送乐视主题（按键映射、顶栏、列数都靠它）

不推主题的话，桌面用编译期默认配置——输入源键（scancode 187）没反应、设置键走系统设置而不是我们的面板、格内会显示 APP 名称。

```bash
cd .
./tools/venv/Scripts/python.exe -I tools/b64push.py themes/letv-x4/config.json /sdcard/Android/data/com.gathin.tvhome/files/config.json
adb -s $TV:5555 shell "su -c 'cp -f /sdcard/Android/data/com.gathin.tvhome/files/config.json /data/data/com.gathin.tvhome/files/config.json'; am force-stop com.gathin.tvhome; settings put secure enabled_accessibility_services com.gathin.tvhome/.HomeKeyService; settings put secure accessibility_enabled 1; sleep 2; am start -n com.gathin.tvhome/.MainActivity"
```

注意 force-stop 后要**再补一次两条无障碍 settings**（同步骤 2，见 `开发文档.md` §1.3）。

### 步骤 7（可选）：开机画面处理

当前这台机器的选择（2026-10-23 最终状态）：**苹果 logo 版开机动画**（此前按用户要求删过一阵，后又换回苹果版）。两个方向按需选择：

**A. 安装苹果版**（当前机器的状态）：

```bash
cd .
./tools/venv/Scripts/python.exe -I tools/b64push.py bootanim/bootanimation-apple.zip /data/local/tmp/bootanimation.zip
adb -s $TV:5555 shell "su -c 'mount -o rw,remount /system && cp /data/local/tmp/bootanimation.zip /system/media/bootanimation.zip && chown root:root /system/media/bootanimation.zip && chmod 644 /system/media/bootanimation.zip'"
adb -s $TV:5555 shell "su -c 'md5sum /system/media/bootanimation.zip'"    # 期望 83c7ca16faf44f2f8f9429029824e543
```

**B. 删除开机视频**（用户要求"暂时取消"过；`/data/fastplay` 那套 SDK 路子在本机无效，直接删 AOSP 开机动画文件）：

```bash
adb -s $TV:5555 shell "su -c 'mount -o rw,remount /system'"
adb -s $TV:5555 shell "su -c 'ls -la /system/media/bootanimation.zip'"      # 先确认存在、记下大小
adb -s $TV:5555 shell "su -c 'cp /system/media/bootanimation.zip /system/media/bootanimation.zip.letv-backup'"   # 留个原件在设备上
adb -s $TV:5555 shell "su -c 'rm /system/media/bootanimation.zip'"
adb -s $TV:5555 shell reboot
```

本地另有完整备份 `bootanim/original-bootanimation.zip`（原版）和 `bootanim/bootanimation-apple.zip`（苹果 logo 版），恢复时 remount rw 后 push 任一本即可。

> 装完 APK 必须重写两条无障碍 settings 并校验：`pm install -r` 会让 AMS 把绑定失败的服务从 `enabled_accessibility_services` 里摘掉，`accessibility_enabled` 一起变 0（2026-10-23 实测三次）。正确顺序：`pm install` → `am force-stop` → `am start`（让包脱离 stopped）→ 两条 `settings put secure`（**分开执行**）→ `dumpsys accessibility | grep services:` 非空。

ADB 侧快速自检（代替不了真人按键，`input keyevent` 注入不带 scancode，只能用 `sendevent`）：

```bash
adb -s $TV:5555 shell "su -c 'grep -nE \"key (377|189|167)\" /system/usr/keylayout/Vendor_3697_Product_0001.kl /system/usr/keylayout/Vendor_4c65_Product_3d4c.kl'"

adb -s $TV:5555 shell "dumpsys activity activities | grep -m1 mResumedActivity"
```

## 3. 持久性：什么会丢、什么不会

| 项目 | 重启电视 | 重刷固件 | 恢复方法 |
|---|---|---|---|
| APK 安装 | 保持 | 保持（/data 不动） | 重装 |
| 无障碍服务设置 | **保持** | 保持 | 步骤 2 两条 settings |
| 停用原厂桌面/抽屉服务 | 保持 | **丢** | 步骤 3/4 |
| .kl 重映射（Le 键） | **保持**（文件内容持久，挂载状态回 ro 无所谓） | **丢** | 步骤 5.1-5.4 |
| lekeyd 守护进程（/system 三个文件） | **保持** | **丢** | 步骤 5.3 |
| 主题 config.json | 保持 | 保持 | 步骤 6 |
| 删除开机视频 | 保持 | **丢** | 步骤 7 |

> 实测备注（2026-10-23）：无障碍设置两次重启均保持；但旧机器上曾出现在日常使用中被清空一次（重启前用户正常看了 70 分钟电视，原因不明）。迁移后如果设置键突然失灵，先查 `settings get secure enabled_accessibility_services`，为空就补步骤 2 的两条命令。

## 4. 回滚方法（全部可逆）

| 想恢复什么 | 命令 |
|---|---|
| 原厂桌面 | `su -c 'pm enable com.stv.launcher'` |
| 乐视抽屉服务 | `su -c 'pm enable com.stv.globalsetting/.service.GlobalSettingService'` |
| Le 键原行为 | 从 `/data/local/tmp/kl-backup/`（设备）或 `dbg/kl-backup-orig/`（PC）把两个 .kl 拷回 `/system/usr/keylayout/`（先 remount rw），重启 |
| 全局 Le 键守护进程 | remount rw 后 `rm /system/bin/lekeyd /system/bin/lekeyd.sh /system/bin/leplay.sh /system/etc/install-recovery-2.sh`，重启（Le 键仍能在桌面内用，只是别的 App 里不再响应） |
| 开机视频 | remount rw 后 push `bootanim/original-bootanimation.zip` 到 `/system/media/bootanimation.zip`，或直接用设备上的 `.letv-backup` |
| 整个桌面 | `su -c 'pm uninstall com.gathin.tvhome'`，然后 `pm enable com.stv.launcher` |

## 5. 收尾安全提醒（新电视用完也要做）

电视的 ADB（5555）开着且有 root，同网段任何设备都能连。收工时在电视上：关闭「USB 调试」和「网络调试」→ 在「已授权的设备」里撤销本机授权 → 重启。之后用 `python tools/adb-closed.py <IP>` 验证端口已关。
